# 경로별 "최선" 증명 (2026-10-25 overnight)

규칙(전 경로 공통)
- **in-sample 판단 금지**: 판정은 홀드아웃(처음 보는 곡)에서만 한다. 개발셋(`eval/ground_truth`, Slakh train)은 후보·파라미터 선택에만 쓴다.
- **라벨 먼저 의심**: 아래 "라벨 수정"에 적은 오류를 먼저 고친 뒤 채점했다.
- **테스트셋으로 학습·튜닝 금지, 후보마다 1회 판정**: 파라미터가 있는 후보는 개발셋에서 고정한 뒤 테스트를 한 번만 돌렸다.
- **기본값 교체 조건**: 이전 기본값 대비 곡별 paired 차이의 95% 부트스트랩 CI 하한 > 0 (10,000회, seed 0).
- 수치는 곡별 평균, 괄호는 95% CI. 재현 명령은 각 절 끝.

## 사전 등록한 판정 규칙 (결과를 보기 전, 2026-10-24 22:45 고정)

- 베이스 기본값: 제품의 bass 모드 입력은 분리 스템(또는 사용자가 올린 단독 베이스)이므로 **스템 입력 후보끼리** 비교한다
  (`stem_yourmt3` 등 vs 현행 `stem_basicpitch`). 교체 조건은 slakh_realbass(일렉)와 slakh_realbass_up(업라이트)
  **두 실베이스 세트 모두**에서 paired CI 하한 > 0, 그리고 Slakh 신스에서도 하한 > 0.
  믹스 입력(`mix_yourmt3`)은 "전체 곡 → 베이스" 경로의 참고 수치로만 쓴다.
- 분리기: 다운스트림 전사 F1(드럼 = ADTOF 5클래스, MDB 대표·Slakh 보조)로만 판정. htdemucs 대비 MDB CI 하한 > 0일 때만 교체.
- 피치 벤드: 개발셋(dev_bends_up)에서 추출기별 파라미터를 "무벤드 노트 평균 오차 ≤ 2 cent" 조건 아래 F1 최대로 고르고,
  테스트(bendtest_up)는 후보마다 1회. 기본값(opt-in 기능의 추출기)은 테스트 F1 최고 + 무벤드 조건 통과 + 실녹음 안정 노트 오차가 기준선보다 나빠지지 않는 후보.

### 3-4. R4 (ADTOF 파인튜닝) — 실행, 기각

계획서 대비 축소(데이터 접근): 되새김용 ADTOF 데이터셋은 신청제(Zenodo 10084510)라 A3 불가. 검증셋 ENST 드러머 3은 9.6 GB 다운로드에
약 5시간이 걸려 대신 Slakh train 분리 스템 16곡을 검증에 썼다. 학습 = Slakh train htdemucs 드럼 스템 40곡, ADTOF 패키지의 DataLoader·
madmom 전처리·MIDI_REDUCED_5 라벨 그대로, 학습률 1e-4(원래의 1/5), 조기 종료, seed 0 (`eval/adtof_finetune/`).

|---|---|---|---|---|
| A0 공개 가중치 | 0.695 | — | 0.859 | — |

- 클래스별(MDB): 킥 0.902 → 0.932, 심벌 0.680 → 0.723은 올랐고 하이햇 0.810 → 0.747, 톰 0.586 → 0.528은 내려갔다.
- **판정: 기각.** 렌더링 도메인에서 오른 만큼 실제 녹음에서 내려갔다. 계획서의 위험 R1(렌더링 데이터로 인한 망각)과 원칙 5가 실측으로 확인됐다. 실제 녹음 되새김 데이터(ADTOF 데이터셋) 없이 렌더링만으로 파인튜닝하는 방향은 닫는다.

### 3-5. plateau 근거
분리기 3종 교체가 모두 MDB ±0.011 안(CI가 0 포함)이고, 렌더링 스템 파인튜닝(R4)은 오히려 −0.043이다. 클래스별로도 일관된 개선이 없다(톰은 오히려 하락 0.586 → 0.49~0.64).
믹스 대비 스템 입력의 이득(+0.047)은 이미 반영돼 있다.

## 4. 분리 (R3)

다운스트림 전사 F1로만 판정했다. 드럼은 위 3-1을 보라. 베이스는 아래 표(Basic Pitch 원출력, Slakh 20곡, 탐색 지표)다.

| 분리기 | 출처·공개 SDR | 곡당 시간(MPS) | 드럼 MDB Δ | 베이스(BP 원출력) Slakh Δ |
|---|---|---|---|---|
| **htdemucs (현행)** | Demucs v4, MUSDB 9.0 dB | ~15 s | — | — (0.546) |
| htdemucs_ft | audio-separator 목록(Demucs v4 FT) | ~30 s | +0.004 [−0.001, +0.008] | **+0.023 [+0.004, +0.041]** |
| BS-RoFormer (ZFTurbo 4-stem, ep17) | MSST v1.0.12, MUSDB 9.65 | ~60 s | +0.005 [−0.003, +0.015] | +0.013 [−0.037, +0.062] |
| SCNet-XL (ZFTurbo) | MSST v1.0.13, MUSDB 9.80 | ~63 s | +0.011 [−0.002, +0.026] | +0.018 [−0.015, +0.051] |
| MDX23C | MSST v1.0.1, MUSDB 7.15 | — | 미실행(CPU 절약, 가장 약한 후보) | — |

- **판정: htdemucs 유지.** 사전 등록 기준(드럼 MDB CI 하한 > 0)을 만족한 분리기가 없다.
- 탐색 결과: htdemucs_ft는 베이스 다운스트림(BP 원출력)에서 유의한 +0.023을 보였다. 현행 베이스 경로(하이브리드)와 실베이스 세트로 같은 판정을 하는 것은 후속 과제로 남긴다(사전 등록하지 않은 기준이라 이번에는 바꾸지 않음).
- **SOTA 비교**: SDR로는 SCNet-XL(10.08)·RoFormer가 htdemucs(9.0)보다 높다. "Beyond SDR"(2026)이 보고한 대로 SDR 우위가 전사 F1로 이어지지 않았다(차이 ±0.01).
- 가중치 라이선스: MSST 저장소는 MIT이고 가중치 라이선스는 명시되지 않았다. 교체했다면 배포 전 확인이 필요했다.

## 5. 비트 (R5)

Slakh test 20곡(30~90초), mir_eval F-measure(±70 ms). 라벨 오류 2곡(MIDI 격자 위상 어긋남) 제외 18곡이 대표다.

| 추적기 | 비트 F (18곡) | 다운비트 F (17곡) | 비트 F (전체 20곡) | 곡당 시간 |
|---|---|---|---|---|
| librosa (기존 폴백) | 0.809 | 0.314 | 0.742 | — |
| madmom (RNN+DBN) | 0.872 | 0.793 | 0.785 | 22.9 s |
| **Beat This! (final0, DBN 없음) — 채택** | **0.927 [0.829, 0.992]** | **0.878 [0.751, 0.965]** | 0.834 | 6.8 s |
| All-In-One | 0.977 (7곡만) | 0.969 (6곡만) | — | 344 s |

- Beat This! vs madmom: 비트 +0.055 [+0.000, +0.114], 다운비트 +0.086 [−0.014, +0.218]. vs librosa: 비트 +0.118 [+0.033, +0.220], 다운비트 +0.565 [+0.355, +0.763].
- All-In-One은 CPU 부하 완화 요청으로 7/20곡에서 중단했다. 겹치는 7곡에서 Beat This!와 차이가 없고(비트 −0.005 [−0.018, +0.004], 다운비트 −0.006 [−0.017, +0.007]) 50배 느리며 natten 의존성이 무겁다.
- **SOTA 비교**: Beat This!는 ISMIR 2024 기준 DBN 없는 SOTA다. Rubato(2026)의 ASAP 다운비트 67.8은 피아노 전용이고 코드 미공개다.
- **plateau**: 최고 후보 둘(Beat This!, All-In-One)이 겹치는 곡에서 동률이고, 남은 오류는 템포 2배·절반 혼동 곡(Track01901)과 라벨 문제다.

## 6. 피치 벤드 (R7)

벤드를 실제 렌더링에 반영한 세트에서 평가했다. Slakh 렌더러는 일부 정답 벤드를 반영하지 않았다(라벨 점검).
개발 = dev_bends_up(Slakh train 30곡, 벤드 노트 223 / 무벤드 3,575), 테스트 = bendtest_up(Slakh test 중 다른 20곡, 벤드 노트 155 / 무벤드 2,487), 업라이트 실샘플 렌더.
"벤드 노트" = 곡선 |c| ≥ 50 cent가 30 ms 이상. 사전 조건: 무벤드 노트 평균 오차 ≤ 2 cent.

| 추출기 (개발셋 최적 설정) | dev F1 | **test F1** | test P / R | test 벤드 곡선 오차 | test 무벤드 오차 | 조건 |
|---|---|---|---|---|---|---|
| 기준선(벤드 없음) | 0 | 0 | — | 91.9 c | 0.01 c | — |
| **pYIN (채택)** | 0.781 | **0.813** | 0.965 / 0.703 | **31.7 c** | 0.17 c | 통과 |
| CREPE full (MPS) | 0.568 | 0.748 | 0.960 / 0.613 | 35.6 c | 0.11 c | 통과 |
| RMVPE | 0.552 | 0.526 | 0.966 / 0.361 | 58.4 c | 0.07 c | 통과 |
| PESTO | — | 미채점 | — | — | dev 최소 12.3 c | **탈락** |
| Basic Pitch 컨투어 | — | 미채점 | — | — | dev 최소 5.9 c | **탈락** |

- 곡별 paired(테스트): pYIN − CREPE F1 +0.094 [+0.016, +0.183], pYIN − RMVPE +0.391 [+0.236, +0.558]. 벤드 곡선 오차 기준선 대비 −52.5 c [−73.4, −32.9].
- 무벤드 노트: 기준선 0.01 → 0.17 c, paired +0.36 c [+0.05, +0.78]. 사전 허용치(≤ 2 c) 안이며 들리는 수준(~5 c)보다 작다.
- **평가 2 — 실녹음**(Bass_2·Mosquito, 노트 골격 = 현행 파이프라인, 기준 f0 = 평가 대상을 뺀 추출기 중앙값):

| 추출기 | 안정(무벤드) 노트 n | 기준선 → 적용 | 슬라이드 노트 n | 기준선 → 적용 |
|---|---|---|---|---|
| **pYIN** | 717 | 11.40 → 11.21 c (−0.20 [−0.35, −0.08]) | 188 | 172.2 → 131.7 c (**−40.5 [−49.7, −31.8]**) |
| CREPE | 440 | 11.44 → 11.25 c (−0.19 [−0.37, −0.06]) | 129 | 187.2 → 171.0 c (−16.2 [−25.7, −7.2]) |
| RMVPE | 449 | 10.07 → 9.93 c (−0.14 [−0.31, −0.02]) | 114 | 245.0 → 229.9 c (−15.2 [−25.7, −5.0]) |

- 변환 방식 비교(개발셋, pYIN): 평활 창 30/60/100 ms는 결과에 영향이 없었다. 데드밴드 20 c는 무벤드 흔들림 2.8 c(조건 탈락), 35 c는 0.82, 50 c는 0.59.
  "슬라이드 판정 노트에만 적용"(데드밴드 20)은 F1이 같고(0.781) 흔들림이 0.58로 더 작았다. 사전 규칙(F1 → 벤드 오차)으로는 동률이라 "전체 노트 + 데드밴드 35"가 선택됐다. 테스트는 이 설정으로 1회만 판정했다.
- **SOTA 비교**: 베이스 MIDI 벤드 추정의 공개 벤치마크는 없다. f0 추출 자체의 SOTA인 PESTO(MIR-1K RPA 97.7)와 RMVPE는 보컬로 학습했다. 저음 베이스에서는 신뢰도 척도가 맞지 않거나(RMVPE: 0.5 초과 프레임 14%) 흔들림이 커서(PESTO) 고전적인 pYIN에 졌다.
- **plateau**: 개발셋 격자 162개 설정에서 pYIN F1이 0.781로 평평하다(평활·데드밴드 무관). 남은 재현율 손실(0.70)은 어택 30 ms 안에서 시작하는 벤드(45%)다.
